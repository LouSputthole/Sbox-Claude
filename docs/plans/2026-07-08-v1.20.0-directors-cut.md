## Per-family implementation pattern (agents: follow exactly)
- New handler file per family in `sbox-bridge-addon/Editor/` modeled on `GameFeelHandlers.cs`
  (register in the same way that file does; read it first).
- New/extended TS module in `sbox-mcp-server/src/tools/` modeled on `gamefeel.ts`, registered in `src/index.ts`.
- Generated game code: `sealed Component`, `[Sync(SyncFlags.FromHost)]` for host-auth state,
  `Math/MathF/MathX` all fine, NO `Array.Clone()`, fully-qualify `System.Collections.Generic.List`,
  `TimeUntil`/`TimeSince` for timers, switch-expressions OK in .cs (NOT in `@code` Razor blocks),
  Razor output must pass `razor_lint`, C# must pass `sandbox_lint`.
- **Verify-gate is not optional:** each scaffold gets generated into the live project, hotloaded,
  `get_compile_errors` checked clean, then the verify files deleted.

### Gate results

All **15 codegen scaffolds** were generated into the live Gravehold project, hotloaded,
compile-checked, and confirmed to load as a `Component` in the `TypeLibrary`. **The gate caught a
real SDK bug:** generated code called `.IsValid` on `Sandbox.Connection`, which has **no
`IsValid` member** on this SDK — 3 sites (`create_host_rpc_action` ×2, `add_targeted_rpc`,
`create_gacha_drop_table`). Fixed to null checks, regenerated, all 15 then compiled clean. Lesson
added to `CLAUDE.md`'s API-differences list. The 4 MovieMaker tools are wire/play tools (not
codegen) and were live-verified separately.
