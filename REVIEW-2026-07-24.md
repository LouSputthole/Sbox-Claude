## 2. The pre-merge review (5 parallel reviewers) — what it caught

Run on `5c9cadb..HEAD` before merge, per standing release discipline.

**Release-blocker (fixed pre-merge):** the MCP-stringification unwrap had been applied to
**rotation parsers only**. All three vector parsers — `ParseVector3Flexible` (MyEditorMenu),
`PlacementPlanV2Helpers.ParseVector`, `CameraCaptureService.ParseVector3Element` — still threw
(or silently mis-parsed via digit-scan, key-order dependent) on the identical stringified-JSON
input, while the CHANGELOG claimed both halves were fixed. All three now unwrap first, same
contract as `ParseRotation`. Lesson: the live verification had only probed rotation — the
review's mechanical grep for `TryUnwrapStructuredJsonString` call sites found the asymmetry
in seconds.

**Also fixed pre-merge:** `gen-codex-plugin.mjs` hardcoded release date (generated changelog
would have stamped 2.2.0 with 2.1.0's date); a generated sentence claiming a `v2.2.0` tag
"predates the Codex package" (false — created by a blanket version sweep); the double-"first
Codex distribution" claim across two CHANGELOG entries; stale `CLAUDE.md` status line;
`## Unreleased` heading missing keep-a-changelog brackets; stale screenshots-on-disk guidance
in TROUBLESHOOTING.md.

**Deferred, logged, non-blocking:**
- `System.Diagnostics.Process` handles in the multiplayer harness never `Dispose()`d (finalizer
  covers it; cap is 2 clients — minor leak on repeated cycles).
- Camera-baseline eviction: refreshed baselines keep their original queue position, so the
  64-entry/64 MiB budget can evict a just-updated baseline before a stale one.
- `StartMultiplayerTestHandler` XML doc omits `spawnErrors` + `waitForJoinSeconds` from its
  return-shape list.
- Codex plugin changelog is an overwrite-template (each release replaces the prior entry) —
  works, but an append-per-release generator would preserve history.

**Open verification item:** the Codex plugin's bundled `.mcp.json` uses the camelCase
`mcpServers` wrapper. A prior automated review (PR #9) claimed Codex requires `mcp_servers` or
a direct map; a verification pass scored the concern 25/100 (leaning fine, couldn't confirm
against a live install). **Settled only by the manual Codex install smoke** — install from
`codex-v2.2.0`, new session, ask for `get_bridge_status`. If the tool is missing, the fix is a
one-line generator change + `codex-v2.2.1`.
